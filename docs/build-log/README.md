# Build log

Frozen records of how a feature was built — mostly snapshots of the live progress board
that ran during the build, plus the occasional close-out written afterward. Each file is a
point-in-time record, not a document that gets maintained — if a claim in one of them
contradicts `docs/decisions.md`, `CLAUDE.md` or the code, **the record is the stale one**
and should be read as history.

Nothing in here is authoritative. It exists so that "why does the app look like this, and
what was rejected along the way" has an answer six months from now.

| Record | Covers |
|---|---|
| [creation-flow-2026-08-08.html](creation-flow-2026-08-08.html) | The organizer's creation flow — design frames `1a`/`1b`, D-027 through D-033. Nine builders, four blind critics, the fixes that came back, and the final gate. |
| [build-board.html](build-board.html) | Closing the loop: create → share → vote → live result. The acceptance script that defined "done", per-workstream critic verdicts, and a dated log. |
| [endgame-progress.html](endgame-progress.html) | The endgame screens — All Vetoed and Tie (D-051). Phase status, per-iteration builder/critic/blind-judge verdicts. |
| [assisted-add-2026-08-11.md](assisted-add-2026-08-11.md) | The Assisted Add (D-052). Stage 0's two gates and what they measured, the SSRF and injection findings, the blind A/B trajectory, real-backend timings, and the deliberate leftovers. |

The HTML ones open directly in a browser; they are self-contained, with no assets and no
JavaScript.
