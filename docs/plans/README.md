# Plans

One file per feature: `docs/plans/<feature>.md`, written before implementation.

A plan should cover: what's being built and why (tie it to a PRD requirement), the data model
touched, the API surface, the failure modes, and how it will be verified. Reference the relevant
`D-00N` entries from [../decisions.md](../decisions.md) so a plan can't quietly contradict a
settled decision.
